# CodexPet UI 精简 + 中文任务文本 —— 设计文档

日期：2026-08-14
状态：待评审

## 1. 目标

把 320×240 屏幕从「仪表盘」变成更像宠物：

1. **中文任务文本**：任务行能正确显示中文（当前中文会变成 `?`）。
2. **精简分区（方案 B）**：用更少、更克制的文字层替代现在密集的顶栏/等级行/底栏，让猫成为视觉主角。

## 2. 范围

本轮只做两件事，对应 Part 1 和 Part 2。

**明确不做（下一轮或以后）：**

- DSH 作为第二个 agent 源接入 bridge（`dsh_monitor.py` / Cordis 插件）。
- 猫的画风、尺寸、帧升级（方向 C）。
- 多页面 / 按键翻页（用户当前无按键）。
- UI 标签（状态名、等级、用量、余额）中文化 —— 保持英文短标签。

## 3. 现状与问题

### 3.1 当前布局（来自 `main.cpp::drawStatusBar`）

| 区域 | 高度 | 内容 |
|---|---|---|
| 顶栏 | 26px (y0–26) | `CODEX PET`（大标题）+ 状态名 + `ONLINE/OFFLINE` + `WiFi/No WiFi` |
| 等级行 | 10px (y28–38) | `Lv.x exp a/b tasks:n` |
| 猫区 | 128px (y64–192) | 320×128 画布，猫踱步/追蝴蝶 |
| 任务行 | 14px (y198–212) | `task: ...`（ASCII） |
| 底栏 | 26px (y214–240) | 用量（左下）+ 鲸鱼 + 余额（右下） |

问题：顶栏 4 段文字 + 等级行 + 任务行 + 底栏，共 5 层文字，信息密度高，像仪表盘。

### 3.2 中文无法显示的原因

- 固件用 Adafruit_GFX 内置 GLCD 字体，只含 ASCII（0x20–0x7E），无中文字模。
- `main.cpp::sanitizeTaskLine()` 主动把非 ASCII 字节替换成 `?`。
- bridge 端已正确按 UTF-8 发送任务文本（`ble_server.py` 的 `task.encode("utf-8")`，且 63 字节处已避免切断多字节字符），因此**只需改固件渲染层，bridge 不动**。

## 4. Part 1 —— 中文任务文本

### 4.1 方案

引入 [U8g2_for_Adafruit_GFX](https://docs.arduino.cc/libraries/u8g2_for_adafruit_gfx/)（olikraus，把 U8g2 字库接到 Adafruit_GFX 显示栈上）+ **wqy 中文字库**：

- 字体：`u8g2_font_wqy12_t_gb2312`（文泉驿 12px，GB2312 编码，透明位图字体）。
- 字库放 flash（16MB 充足）；PSRAM 不用于字体，预留给后续猫动画帧。
- 新增 `src/ui/chinese_text.{h,cpp}`，提供 `drawChineseText(Adafruit_GFX&, x, y, const char* utf8, maxPx)`：
  - UTF-8 解码为 Unicode 码点；
  - Unicode → GB2312 两字节码查字模；
  - 按像素宽度累计，超过 `maxPx` 停止；
  - 只在 UTF-8 序列边界处停止，**绝不切断半个中文字**。

### 4.2 涉及文件

| 文件 | 改动 |
|---|---|
| `firmware/platformio.ini` | `lib_deps` 增加 `olikraus/U8g2_for_Adafruit_GFX` |
| `firmware/src/ui/chinese_text.h/.cpp` | 新增：UTF-8→GB2312 + 中文字模渲染 |
| `firmware/src/main.cpp` | 删除 `sanitizeTaskLine()`；任务行改用 `drawChineseText` |

### 4.3 截断与回退

- 超宽：按像素宽度截断，末尾不加 `?`。
- 非 GB2312 字符（生僻字、emoji）：渲染为占位（如 `□` 或空格），不破坏整行。
- GB2312 覆盖约 6763 常用汉字，覆盖日常中文（含「看看我的猫有什么可以优化的吗」）足够。

### 4.4 待验证项

- `u8g2_font_wqy12_t_gb2312` 在 `U8g2_for_Adafruit_GFX` 中是否需要额外 `#include` / 大字体开关。
- UTF-8→GB2312 转换需要一张约 7KB 的 Unicode→GB2312 映射表（已知做法，实现时确认）。
- 若 wqy12 体积/转换表过重，备选：缩小到更小子集字库（但任务文本是任意中文，优先保留全 GB2312）。

## 5. Part 2 —— B 精简布局

### 5.1 新分区

四段式，去除大标题与冗余文字，猫区成为主体：

| 区域 | 高度（约） | 内容 |
|---|---|---|
| 顶栏 | 20px | 左：状态名（size1, cyan）；右：`● BLE` `● WiFi` 彩色圆点（size1，绿/红） |
| 猫区 | 148px | 320 宽画布，猫居中；上下留呼吸空间 |
| 任务行 | 24px | 中文任务文本（12px），超宽时横向滚动 |
| 底栏 | ~20px | 单行小字：`Lv.x` ＋ 今日用量 ＋ `🐋 余额`，三者并排 |

要点：

- 删除 `CODEX PET` 大标题；`ONLINE/OFFLINE` 整词改为彩色圆点（绿=在线、红=离线），BLE 与 WiFi 各自一个圆点。
- 等级行的 `exp a/b` 与 `tasks:n` 从独立行收进底栏的 `Lv.x`（完整经验/任务数仍可从 WebUI `/api/status` 查看，不进主屏）。
- 任务行不再拼 `task:` 前缀（任务文本已经是内容本身），只显示任务文本。

### 5.2 猫的尺寸

- **本轮不改猫的绘制尺寸**：猫仍为现有程序化造型（约 66px 高，在 128px 画布内踱步/追蝴蝶）。
- 「猫更大」的观感通过**压缩上下文字层、给猫更多留白**获得。
- 猫的物理放大 / 造型升级属于方向 C，届时再引入缩放系数重构绘制。

### 5.3 涉及文件

| 文件 | 改动 |
|---|---|
| `firmware/src/main.cpp` | 重写 `drawStatusBar()`：四段式、圆点状态、中文任务行、底栏单行 |
| `firmware/src/pet/pet_animation.h` | 若猫区垂直位置/画布高度微调，同步 `CANVAS_H` 与 blit 目标 y |

### 5.4 精确坐标

各 band 的最终 y 坐标在实现时于真机上肉眼校准（字体行高、圆点大小、留白）。上表数值为初始目标，允许 ±4px 微调。

## 6. 数据流（不变）

```
Codex hooks / JSONL  →  bridge StateHub  →  BLE  →  ESP32  →  屏幕
                        (bridge 不动)
```

中文任务文本链路：`codex_monitor.py` 提取 UTF-8 文本 → `ble_server.py` 写 TASK 特征 → `ble_manager.cpp` 存 `taskText_` → 本轮新 `drawChineseText` 渲染。

## 7. 错误处理

- 任务文本过长：像素宽度截断，不越界、不切断中文字。
- 含非 GB2312 字符：占位符，不崩溃。
- 字体/字库缺失（编译期）：回退到 GLCD 字体 + 中文显示为 `?`（保持现状，不崩溃）。
- 空任务文本：显示 `-` 或空行（沿用现有 `task: -` 语义，去掉前缀后显示 `-`）。

## 8. 验收标准

- [ ] 中文任务文本在设备上清晰可读（12px，无乱码/无 `?`）。
- [ ] 超宽中文任务行能滚动/截断，不压到余额区。
- [ ] 顶栏只有状态名 + 两个彩色圆点，无大标题。
- [ ] 底栏单行：Lv / 用量 / 余额，不重叠。
- [ ] 猫区留白增加，猫为视觉主体。
- [ ] 编译通过、烧录成功、`FPS ≥ 20`、无内存泄漏（启动与运行日志正常）。
- [ ] BLE/WiFi 圆点颜色随在线状态正确变化。

## 9. 风险与待验证

1. **中文字库依赖细节**：wqy12 在 U8g2_for_Adafruit_GFX 的引入方式与体积需实测（§4.4）。
2. **UTF-8→GB2312 映射表**：需 7KB 左右表，实现时确认来源与正确性。
3. **猫区高度**：画布高度微调可能影响 `ground` 基线，需真机确认猫不贴边、符号（`?`/`Zzz`/星星）不被裁。
